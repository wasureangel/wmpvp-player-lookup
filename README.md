# CS2 玩家查询 · 本机网页版

在自己电脑上运行的完美平台玩家查询工具。浏览器访问 `http://127.0.0.1:8765/`，由本机 Python 服务处理登录和查询。项目已恢复为本地运行，不再使用 Cloudflare Pages / Functions。

## 启动

需要 **Python 3.10 或更新版本**，只使用标准库，无需安装 Python 依赖。Windows 安装 Python 时启用命令行入口，随后双击 `启动网页版.cmd`；启动器也支持项目内已有的 `runtime/pythonw.exe`。

也可以在项目目录运行：

```sh
python web_app.py --open
```

浏览器会打开本机网页。关闭浏览器不会停止后台服务；电脑或服务重启后，需要重新启动、重新登录。GitHub 源码不包含内置 Python 运行时，首次下载请先安装 Python。

## 查询功能

- 每次最多 20 个昵称，按行输入，也可粘贴游戏控制台 `status` 输出。
- 过滤名单按完整昵称匹配，**查询前直接跳过**，不请求这些玩家的战绩和历史分数。修改名单不隐藏已有结果，下次查询生效。
- 同名账号中有近期对局时，排除已确认无对局的账号；全部有或全部无时都显示。查询失败的账号保留提示，模糊匹配由用户确认。
- 展示最近十场逐场战绩：日期、类型、胜败、比分、K/D/A、ADR、RWS、Rating Pro、WE、级别、高光。移除了旧的场均统计圆环，不再计算汇总胜率、爆头率及 K/D。
- 日期优先显示结束时间，比分采用客户端截图的队伍 2 : 队伍 1 顺序；胜败根据该玩家所在队伍判断，平局显示“平”。缺失数值显示 `--`。
- Rating Pro 低于 1 显示红色，高于 1 显示青色，等于 1 保持原色。
- 顶部显示当前天梯分、历史分及对应图标；超过 2400 分统一使用基础青绿色 S。历史分取各赛季 `historyScores` 的最高有效值，不保证完整生涯覆盖。
- 官匹分只取最近十场比赛列表里最新的有效 `pvpNormalRank`，全部为空不显示；不会用详情里的默认零覆盖空值。
- 保留黄色方形 MVP，以及“准、狙、突、残、闪、助”高光图标，不显示 SVP。
- 页面不展示封禁记录、64 位 ID、平台昵称或分数变化，不提供报告下载；网页版不请求封禁记录。

## 高光来源与限制

优先合并比赛列表及该玩家详情中的明确高光标记。部分完美官匹 Pro 比赛的整场 `honor` 都为空，此时仅在完整十人数据可用时补全：

| 图标 | 详情字段 | 含义 |
|---|---|---|
| 准 | `headShot` | 爆头次数最多 |
| 狙 | `snipeNum` | 狙击击杀最多 |
| 突 | `entryKill` | 首杀最多 |
| 残 | `endGame` | 残局获胜最多 |
| 闪 | `flashSuccess` | 闪白成功最多 |
| 助 | `assist` | 助攻最多 |

各项取正数最高值，并列时取接口记录顺序的第一位。这个补全方式与用户提供的八场客户端截图相符，尚不能保证覆盖客户端所有特殊规则；缺失数据不会当成零推算。悬停补全图标可查看来源说明。MVP 使用平台已有标记，不通过以上规则生成。

## 登录和隐私

在网页输入手机号，点击发送验证码，亲自完成完美官方人机验证，再输入短信验证码登录。登录后可验证战绩权限。

官方登录凭据只保存在本机服务内存中，不写入项目文件，不提交到 GitHub。退出本机登录或重启服务会清除它们。本机服务只监听 `127.0.0.1`，接口检查访问来源及页面令牌。平台接口和验证码的可用性仍取决于完美服务。

## 开发与仓库检查

应用运行不需要 Node.js。维护前端时可使用 Node.js 22 或更新版本：

```sh
npm run check
npm test
python tests/local_web.py
```

GitHub Actions 运行以上离线代码检查，不发送短信，不登录真实账号，也不自动部署。实际页面、登录及战绩效果由使用者验收。
